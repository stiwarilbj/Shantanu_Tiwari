# Evolution Simulator walkthrough plan

[Open Evolution Simulator in Project Lab](https://stiwarilbj.github.io/Shantanu_Tiwari/experiments/evolution-simulator/)

Use the full 11-minute MinuteLabs walkthrough as a sequence of things visitors can try. Begin with one creature looking for food, then pull back to explain a population. Finish with two runs that differ in one setting and give visitors a way to test their own explanation. Keep Project Lab’s shared navbar and use its own visual identity, creature art, copy, icons, and illustrations. [Interactive Evolution Simulator by MinuteLabs.io](https://www.youtube.com/watch?v=6nMo8T3T0L4)

## What the review covers

- **Video pass.** Review the official storyboard from the opening drawings through the end card at five-second intervals. Use the project’s earlier timestamped notes for narration details. The exact narration and motion between sampled frames still need direct playback verification. The time links below lead to the beginning of each relevant segment. [Official video](https://www.youtube.com/watch?v=6nMo8T3T0L4)
- **Interaction pass.** Trace each scene to the closest live control or demo. The first twelve About chapters cover the field through a 5:02 Trends lesson. The paired experiment, staged comparison, and Age walkthrough already exist on other parts of the app. [Chapter data](src/guide.js), [About](src/components/About.vue), [Compare](src/components/Compare.vue), [Trends](src/components/Trends.vue)
- **Model and architecture pass.** Compare the April launch-era code with Project Lab’s engine, then check which behavior is versioned. The video shows the interface and tells a story about the model. The public source establishes the documented architecture at a specific commit. Identifying the exact deployed build used in every shot would require more evidence. [Launch snapshot](https://github.com/minutelabsio/evolution-simulator/tree/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3), [Local rules](src/engine/config.js)
- **Layout pass.** Treat the Project Lab navbar as the top edge of the experience and the simulator as the surface below it. The checked-in Pages build meets the navbar edge at the tested desktop, split, and phone sizes. The staged Compare sequence is a confirmed exception. At 1440×900 it begins at the viewport top and intercepts clicks in the navbar’s 54 px area. Escape returns focus to the launch button. [Site integration styles](src/project-lab.css), [Pages browser tests](browser/project-lab.spec.js)

## 2. Layout and interaction specifications

- **Page frame.** The universal Project Lab navbar is the upper boundary. Render the simulator flush with its bottom edge and with both sides of the viewport. The stage fills the available area before the control rail. On a short window, keep controls reachable in one simulator scroll area. Keep the existing phone navigation behavior, including its space for an expanded menu. [Project Lab shell styles](src/project-lab.css)
- **World.** Keep the wide oblique view, a near-field follow view, and a north-up overhead view with a reset control. Use an original matte off-white field, readable gray refuge edges, small olive food markers, and slate-blue surroundings. Draw subtle shadows, sense discs on the field, and a quiet selection outline. Place the text readout away from the tracked target so it leaves the food contact visible. Run picking and labels through the rendered camera’s projection at each size. [Board](src/components/Board.vue), [World](src/components/World.vue)
- **Playback.** Keep day, elapsed time, and the primary play action visible together. Group step, speed, and replay actions by the clock. Mark the chapter’s key events on the existing seek rail with text for focus or tap. In the day ribbon, retain selection, the metric legend, and extinction tiles. A tap pins event details. Enter on an event marker seeks. Dragging the rail previews the selected time, and a pause state stays paused on release. [World player](src/components/World.vue), [Generation ribbon](src/components/Ribbon.vue)
- **Lesson controls.** Use a narrow progress row with the chapter name, step count, and **Back**, **Next**, and **Exit walkthrough**. The main action opens the next live view. Keep explanatory text to one paragraph per beat with optional details for formulas. Put the timestamp link alongside the caption. On phones, wrap to a compact navigation row and show the current description below the board. Retain the selected lesson across reload. [About](src/components/About.vue), [Route handling](src/App.vue)
- **Settings.** Use the same surface over World and Trends. Group species and inherited traits first, then energy and food, then duration, seed, and launch mode. Keep exact numeric entry beside each adjustable mutation control and put alternate rules under Advanced. Use one scrollable column on narrow phones and keep the run action in view. Draw attention to the field changed in the lesson with its label and focus outline. Preserve the active run and unsaved Settings draft until the visitor confirms a change. Show a separately editable copy when opening a guided setup. Closing returns focus to the launcher and preserves the prior chart or playback state. [Settings](src/components/Settings.vue)
- **Trends.** Keep the first five plots in their established order, Population, Age, Speed, Size, and Sense Range. Label the current phase, scope, spread method, and units near the shared controls. Highlight a focused plot while keeping neighboring signals visible. Provide a readable table and an explicit **Watch day** action, including on touch. A run with no observations in the active scope shows a gap or empty state with an explanation. [Trends](src/components/Trends.vue), [Plot controls](src/components/TrendPlot.vue)
- **Compare.** Use equal board areas above a compact side-by-side readout at desktop widths. At phone widths, stack the boards under one shared transport. Keep seed, day, elapsed time, and size spread visible when a board is de-emphasized. Show a stable center split on wide screens. Keep a static before-and-after option, manual stepping, and an explicit return to the full chart view. Stop and restore keyboard focus when the user presses Escape, exits the route, or cancels a replay. [Compare](src/components/Compare.vue)
- **Accessibility.** Keep visible focus rings and named controls for selecting a blob, stepping the replay, adjusting range, and switching cameras. Pair color with text, shape, or a labeled legend. Announce pause beats and job states without announcing each frame. For reduced motion, use manual camera cuts and hold the same annotated pose until the visitor continues. Keep signals and controls available in the Canvas fallback. [World](src/components/World.vue), [Board](src/components/Board.vue)

## 3. Simulation and data specifications

| Decision | Implementation contract |
| --- | --- |
| **Day loop and resources** | Keep the seeded 500-unit field, fresh food and energy at dawn, per-run day-end settings, and versioned ways of reaching refuge. One credit plus refuge lets a blob survive, and two or more plus refuge allow one offspring. The zero-reward default gives one credit for either meal and zero restored energy. Keep the existing last-generation result and extinction stop. [Simulation](src/engine/simulation.js), [Configuration](src/engine/config.js) |
| **Movement and cost** | The walkthrough model uses linked stride, so same-speed blobs with different size can travel different distances in the same 0.1-second move. For walkthrough metabolism, charge `(size³ × distance per move² + sense) ÷ 10,000` at a move. Show the actual run’s cost rule and units when opening a different metabolism profile. Keep the renderer’s interpolation independent of the model clock. [Geometry and cost](src/engine/geometry.js), [Playback interpolation](src/live-playback.js) |
| **Predation boundary** | For current setups, the prey’s raw size must be at most 80% of the hunter’s raw size. For a size-10 prey that means at least 12.5. Size comparisons, sight, contact, species settings, and the prey event all have separate roles. Keep the older 1.20× rule when replaying rule version 1. [Project Lab threshold](src/engine/geometry.js), [Reference calculation](https://github.com/minutelabsio/evolution-simulator/blob/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3/src/wasm/src/simulation/behaviours/cannibalism.rs) |
| **Mutation and the matched pair** | For the guided pair, use seed 118, rule version 4, walkthrough foraging, 50 founders, 50 plants per day, and 600 days. Vary only size standard deviation, 1.00 and 0.50, which correspond to variances of 1.00 and 0.25. Use 100 days for the explicitly labeled preview. Display values from the actual simulation, with seed, phase, and sample size. Preserve archived rule versions, including saves with stored variance. [Paired setup](src/experiments.js), [Launch sampler](https://github.com/minutelabsio/evolution-simulator/blob/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3/src/wasm/src/creature/mutatable.rs) |
| **Generations and statistics** | Define dawn as the opening cohort and dusk as the closing roster. Ages count days survived, with age zero at birth. Keep living age, age at death, and newborn shares distinct. For the walkthrough spread use sample standard deviation clipped by the extrema. Preserve percentiles as an option. Provide the row’s sample count and keep missing values empty. [Statistics](src/engine/stats.js), [Trends](src/components/Trends.vue) |
| **Evidence from replays** | Define teaching moments in terms of a stable creature ID and an observed event, cohort, or completed time. Keep the prior frame if a new replay fails, and show a retry for the failed scene. If an event is missing in a visitor’s custom run, say so and offer the known demonstration or next valid event. [Guide replay](src/guide-replay.js), [Track reconstruction](src/track.js) |

## 4. Architecture and state

The launch source has a generation-addressed Vue shell, worker requests for simulation and statistics, a Rust/WebAssembly engine, camera-aligned WebGL and HTML layers, and a static deployment base. Project Lab already has corresponding boundaries in Vue and Vite, a seeded JavaScript worker, day checkpoints, and Three.js with a Canvas fallback. The walkthrough can reuse these existing parts. [Launch routes](https://github.com/minutelabsio/evolution-simulator/blob/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3/src/router/index.js), [Launch worker](https://github.com/minutelabsio/evolution-simulator/blob/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3/src/workers/simulation.js), [Launch renderer](https://github.com/minutelabsio/evolution-simulator/blob/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3/src/components/three-vue/v3-renderer.js), [Launch build](https://github.com/minutelabsio/evolution-simulator/blob/3b99f358b70a608f5fb3e34fe8f410ba85aec7f3/vue.config.js)

1. **Chapter data.** Extend the existing lesson entries with a target screen, fixture or preset ID, and optional day, cohort, camera, selection, overlay, or chart instructions. Extend the existing example lookup so settings, charts, and Compare can be scene destinations. Keep the per-scene state in the receiving component. Preserve all existing lesson IDs and add one stable key for each later scene. [Guide data](src/guide.js), [Route coordinator](src/App.vue)
2. **Navigation and return.** Use the current day-addressed hash on the static Pages route. Let history represent explicit lesson, view, and phase changes. Replace history for scrubbing and other continuous changes. Preserve scroll, chart range, and focus on return. Validate IDs and day bounds on load. A chapter link in a fresh browser reconstructs its known fixture. A link to a custom local run offers the saved setup or a fresh scene when the run is unavailable. [App shell](src/App.vue), [Setup import and export](src/export.js)
3. **Simulation ownership.** Let the worker own RNG, movement, contacts, day settlement, and stats. Let Vue request jobs and manage controls, and let each renderer consume frames. Keep paired results keyed by seed, rule version, and horizon. Reuse temporary results across chapters during a walkthrough. Persist demo runs only on an explicit save in the guided path. Keep the current library actions for saving a normal paired run. [Worker](src/engine/worker.js), [Store](src/store.js), [Archive](src/archive.js)
4. **Cancellation and recovery.** Use existing abort signals and request tickets across page changes, scope changes, and retries. A canceled or stale job cannot select a new replay or write a partial result to the active run. If part of a pair fails, keep the ready side visible with a retry on the affected side. Make existing saved runs, branches, exported files, and URLs regression fixtures. [Store](src/store.js), [Compare replay loading](src/components/Compare.vue)
5. **Rendering and packaging.** Keep board, camera, and hit testing in Board. Pass display options from each view. Scope any new CSS and motion to the simulator. Keep the existing lazy view loading and relative asset paths, and rebuild the Pages output after implementation. [Board](src/components/Board.vue), [Vite configuration](vite.config.js), [Project build instructions](README.md)
